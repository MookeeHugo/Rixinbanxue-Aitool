# 屏幕共享功能文档 - 2025年11月21日

## ✅ 功能状态

**屏幕共享功能已完全实现并可用！**

这个功能允许教师（或任何参与者）在直播课堂中共享自己的屏幕，学生可以实时看到共享的内容。非常适合：
- 📊 展示 PPT 演示文稿
- 💻 演示代码编写过程
- 🌐 浏览网页讲解
- 📝 展示文档内容
- 🎮 演示软件操作

## 📋 技术实现

### 1. 核心技术栈

- **LiveKit SDK**：使用 `@livekit/components-react` 和 `livekit-client`
- **WebRTC**：底层使用 WebRTC 的 `getDisplayMedia` API
- **React Hooks**：状态管理和副作用处理

### 2. 关键组件

#### LiveVideoDisplay.tsx

**文件路径**：`src/components/live/LiveVideoDisplay.tsx`

**核心功能**：

```typescript
// 监听屏幕共享轨道
const tracks = useTracks(
  [
    { source: Track.Source.Camera, withPlaceholder: true },
    { source: Track.Source.ScreenShare, withPlaceholder: false }, // 屏幕共享轨道
  ],
  { onlySubscribed: false }
);

// 使用 GridLayout 自动布局视频和屏幕共享
<GridLayout tracks={tracks} style={{ height: '100%', width: '100%' }}>
  <ParticipantTile />
</GridLayout>
```

**MediaControlsHandler**：

```typescript
useEffect(() => {
  if (!localParticipant) return;

  const updateScreenShareState = async () => {
    try {
      // 启用或禁用屏幕共享
      await localParticipant.setScreenShareEnabled(screenShareEnabled ?? false);

      // 同步实际状态回父组件
      const isScreenShareEnabled = localParticipant.isScreenShareEnabled;
      if (onScreenShareToggle && isScreenShareEnabled !== screenShareEnabled) {
        onScreenShareToggle(isScreenShareEnabled);
      }
    } catch (error) {
      console.error('设置屏幕共享状态失败:', error);

      // 如果失败（比如用户拒绝权限），通知父组件关闭
      if (onScreenShareToggle && screenShareEnabled) {
        onScreenShareToggle(false);
      }
    }
  };

  updateScreenShareState();
}, [screenShareEnabled, localParticipant, onScreenShareToggle]);
```

**关键特性**：
- ✅ 自动处理屏幕共享权限请求
- ✅ 错误处理（用户拒绝权限时自动回退）
- ✅ 状态同步（确保UI状态与实际状态一致）
- ✅ 支持多参与者同时查看

#### 主页面集成（page.tsx）

**文件路径**：`src/app/live/[id]/page.tsx`

**状态管理**：

```typescript
// 屏幕共享状态
const [isScreenSharing, setIsScreenSharing] = useState(false);
```

**传递给 LiveVideoDisplay**：

```typescript
<LiveVideoDisplay
  micEnabled={isMicOn}
  cameraEnabled={isCameraOn}
  screenShareEnabled={isScreenSharing} // 传递状态
  onMicToggle={(enabled: boolean) => setIsMicOn(enabled)}
  onCameraToggle={(enabled: boolean) => setIsCameraOn(enabled)}
  onScreenShareToggle={(enabled: boolean) => setIsScreenSharing(enabled)} // 状态回调
/>
```

**控制按钮**：

```typescript
<button
  onClick={() => setIsScreenSharing(!isScreenSharing)}
  className={`p-4 rounded-full transition-all ${
    isScreenSharing
      ? "bg-cyan-600 hover:bg-cyan-700 text-white" // 共享中：青色高亮
      : "bg-slate-800 hover:bg-slate-700 text-white" // 未共享：灰色
  }`}
  title={isScreenSharing ? "停止共享屏幕" : "共享屏幕"}
>
  <MonitorUp size={20} />
</button>
```

### 3. 工作流程

#### 启动屏幕共享

```
用户点击按钮
    ↓
setIsScreenSharing(true)
    ↓
传递给 LiveVideoDisplay
    ↓
MediaControlsHandler 检测到状态变化
    ↓
调用 localParticipant.setScreenShareEnabled(true)
    ↓
浏览器弹出屏幕选择对话框
    ↓
用户选择要共享的屏幕/窗口/标签页
    ↓
LiveKit 开始发送屏幕共享轨道
    ↓
所有参与者收到屏幕共享轨道
    ↓
GridLayout 自动显示屏幕共享内容
```

#### 停止屏幕共享

```
用户点击按钮
    ↓
setIsScreenSharing(false)
    ↓
调用 localParticipant.setScreenShareEnabled(false)
    ↓
停止发送屏幕共享轨道
    ↓
GridLayout 移除屏幕共享显示
    ↓
恢复只显示摄像头视频
```

#### 用户拒绝权限

```
用户点击按钮
    ↓
浏览器弹出权限对话框
    ↓
用户点击"取消"或关闭对话框
    ↓
setScreenShareEnabled 抛出异常
    ↓
catch 块捕获错误
    ↓
调用 onScreenShareToggle(false)
    ↓
UI 按钮恢复为"未共享"状态
```

## 🎯 功能特点

### 1. 浏览器原生选择界面

用户点击"共享屏幕"后，浏览器会弹出原生对话框，允许用户选择：

- **整个屏幕**：共享整个桌面（支持多显示器）
- **应用窗口**：共享特定应用窗口
- **Chrome 标签页**：仅共享特定浏览器标签页（Chrome 特有）

**隐私保护**：
- ✅ 系统级别的权限控制
- ✅ 用户完全控制共享内容
- ✅ 可随时停止共享

### 2. 自动布局

**GridLayout 智能布局**：
- 只有摄像头时：全屏显示视频
- 有屏幕共享时：**屏幕共享占据主区域**，摄像头缩小到角落
- 多人参与时：自动调整布局

**示例布局**：

```
┌─────────────────────────────────┐
│                                 │
│   屏幕共享内容（主显示区域）       │
│                                 │
│                    ┌──────┐    │
│                    │ 摄像头│    │
│                    └──────┘    │
└─────────────────────────────────┘
```

### 3. 视觉反馈

**按钮状态**：
- 未共享：灰色背景 (`bg-slate-800`)
- 共享中：青色高亮 (`bg-cyan-600`)
- 悬停效果：颜色加深

**图标**：`MonitorUp`（显示器向上箭头）表示屏幕共享

### 4. 多参与者支持

**教师共享**：
- 教师点击按钮共享屏幕
- 所有学生实时看到共享内容
- 学生无需任何操作

**学生视角**：
- 自动接收屏幕共享轨道
- 大屏幕显示共享内容
- 教师的摄像头画面缩小显示

### 5. 性能优化

- **自适应码率**：LiveKit 自动调整视频质量
- **带宽优化**：根据网络状况调整分辨率
- **低延迟**：WebRTC P2P 传输

## 🔧 故障排查

### 问题 1：点击按钮后没有反应

**可能原因**：
- LiveKit 连接未建立
- 权限被浏览器阻止

**排查步骤**：
1. 检查浏览器控制台错误
2. 确认 LiveKit 连接状态
3. 检查浏览器权限设置（`chrome://settings/content/screenCapture`）

**解决方案**：
- 等待 LiveKit 完全连接后再点击
- 允许浏览器屏幕捕获权限
- 刷新页面重试

### 问题 2：选择对话框不弹出

**可能原因**：
- 浏览器不支持（很少见，现代浏览器都支持）
- 权限被永久拒绝

**解决方案**：
1. 检查浏览器版本（推荐 Chrome 90+）
2. 重置屏幕捕获权限：
   - Chrome: `chrome://settings/content/screenCapture`
   - 删除当前网站的权限设置
3. 使用无痕模式测试

### 问题 3：学生看不到共享内容

**可能原因**：
- 学生的 LiveKit 连接问题
- 轨道订阅失败

**排查步骤**：
1. 学生端检查控制台错误
2. 确认学生端 `useTracks` 是否接收到 ScreenShare 轨道
3. 检查网络连接

**解决方案**：
- 学生刷新页面
- 教师停止并重新启动屏幕共享
- 检查 LiveKit 服务器状态

### 问题 4：画面卡顿或延迟高

**可能原因**：
- 网络带宽不足
- CPU 使用率过高
- 共享分辨率过高

**解决方案**：
- 降低共享分辨率（选择窗口而非整个屏幕）
- 关闭其他占用带宽的应用
- 检查网络连接质量
- LiveKit 会自动调整，稍等片刻

### 问题 5：声音无法共享

**症状**：共享标签页播放视频时，学生听不到声音

**原因**：
- 默认情况下，某些浏览器不共享系统音频
- 需要在共享对话框中勾选"同时共享音频"

**解决方案**：
1. 启动屏幕共享时，在浏览器对话框中：
   - 找到"同时共享音频"或"Share audio"选项
   - 勾选该选项
2. 确保选择的是"Chrome 标签页"而非"应用窗口"
3. 某些浏览器可能不支持音频共享
