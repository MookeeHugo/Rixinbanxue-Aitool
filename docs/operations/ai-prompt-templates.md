> **文档版本**: v2.4
> **更新日期**: 2025-01-14
> **适用场景**: Hugo使用AI工具（Claude Code/Cursor）开发MVP

## 📖 使用说明

本文档提供**详细的AI指令模板**，Hugo可以直接复制粘贴给AI使用。

### 使用方法

1. **找到对应的任务**（如M1 Step 1）
2. **复制"Hugo对AI说"部分的全部内容**（包括引号内的文字）
3. **粘贴到Claude Code/Cursor对话框**
4. **等待AI生成代码**
5. **按照"Hugo验收清单"逐项检查**

### 注意事项

- ⚠️ **不要修改指令内容**（除非明确说明需要填写具体信息，如Supabase URL）
- ✅ **逐步执行**（完成一个Step再进行下一个）
- 📸 **及时截图**（每个Step验收成功后截图存档）
- 🐛 **遇到Bug**（参考主文档11.1.2的Bug修复模板）

## 🚀 GPT-5.1 实战技巧合集（本项目场景）

> 结合 GPT-5.1 的更长上下文与推理能力，以下模板可直接复制粘贴给 AI，逐条覆盖你刚才提到的六个技巧。

### 技巧 1：长上下文一次性贴全

**适用场景**：需要 AI 理解项目阶段性成果，例如同步 `PROJECT_STATUS.md`、`PROJECT_PROGRESS.md` 与最新设计稿，再生成路线图。

**Prompt 模板**:
```markdown
我会一次性贴出以下资料，请通读后再行动：
- 摘要：<将 PROJECT_STATUS.md 中的最新里程碑粘贴到此>
- 进展：<将 PROJECT_PROGRESS.md 中的摘要段落粘贴到此>
- 依赖：<补充任何新增 API 或供应商资料>

现在请：
1. 总结目前 MVP 处于的阶段
2. 指出阻塞点
3. 给出下一迭代的 3 个优先事项

除非我另行说明，不要省略引用来源，直接写“来源：PROJECT_PROGRESS.md”这种短标签即可。
```

### 技巧 2：Goal + Constraints + Progress 结构化计划

**适用场景**：要求 GPT-5.1 自主规划实现步骤，例如在 `src/app/(dashboard)` 中新增课程列表。

**Prompt 模板**:
```markdown
Goal:
- 在 Next.js App Router 中新增 /dashboard/courses 页面，复用现有 `CourseCard` 组件

Constraints:
- 必须沿用 Tailwind 设计系统
- Supabase 查询只允许命中 `courses` 表，最多 20 条
- 修改后的文件只包含 src/app/(dashboard)/courses/page.tsx 与对应样式

Progress:
- 目前已经有 `CourseCard` 和 `CourseList`，但缺少页面入口
- Supabase 客户端封装在 lib/supabase.ts

请先列出计划步骤，再逐条执行；每个步骤完成后附带“✅ Step X 完成”。
```

### 技巧 3：先确认未知再执行

**适用场景**：数据库 schema 不确定，比如准备扩展性能追踪表。

**Prompt 模板**:
```markdown
我们要在 Supabase 里新增 `lesson_metrics` 表：
- 想跟踪字段：lesson_id、avg_watch_time、drop_off_rate、updated_at

在写 SQL 之前，请先列出你需要确认的所有问题（至少 3 个），等我回答后再执行。对每个问题用列表形式呈现，例如：
- Q1: xxx（为什么需要）
- Q2: xxx
```

### 技巧 4：要求输出 Diff / 分段结果

**适用场景**：修补组件或样式，需要更易 Review 的结果，比如更新 `src/components/HeroSection.tsx`。

**Prompt 模板**:
```markdown
我要将 HeroSection 的 CTA 重构为双按钮，请按以下格式回复：
1. <diff> 包含完整 Unified Diff（文件路径 + 修改）
2. <explanation> 解释每个变更点
3. <tests> 建议的手动/自动测试

上下文（可省略无关部分）：
<粘贴 HeroSection 现有实现或相关片段>
```

### 技巧 5：强制风险 / 引用 / 测试思路

**适用场景**：撰写决策或方案，比如比较 `Supabase Edge Functions` 与 `Next.js Route Handlers`。

**Prompt 模板**:
```markdown
请完成以下任务并遵守格式要求：
1. 方案描述（需要引用来源，引用格式为 [文件名](#L行号)）
2. 风险清单（至少 3 条）
3. 测试思路（覆盖单元 + 集成 + 手动）

输入材料：
- 摘要：<粘贴 data-driven-decisions.md 相关段落>
- 约束：成本 < $50/月，延迟 < 400ms
```

### 技巧 6：区分推理与命令（工具协作）

**适用场景**：需要让 GPT-5.1 明确什么时候应该运行命令，例如请求它在本地执行 `npm run test`。

**Prompt 模板**:
```markdown
我们按以下协议协作：
- 当你觉得需要运行命令时，先用 <plan> 解释原因，再用 <command> 包住要执行的指令
- 除非我写“APPROVED”，你只做推理输出，不真的运行命令

任务：检查最近的 TS 类型错误（编译日志如下），并建议最少的修复方案。
<粘贴 `npm run build` 的错误输出>
```


### 技巧 7：情绪 / 用户访谈分析模板

**适用场景**：需要 GPT-5.1 利用更强的情绪理解与心理分析能力，从用户访谈、客服记录或测试问卷中提炼动机、痛点与情绪趋势。

**Prompt 模板**:
```markdown
访谈背景：
- 用户画像：<填写角色，如“中级英语教师”>
- 访谈目的：<如“验证课程推荐功能”>

访谈逐字稿（按时间顺序）：
<粘贴 `docs/PROJECT_PROGRESS.md`、`rixinmvp.md` 或实际访谈记录中与体验相关的段落，可标明访谈官和受访者>

请输出：
1. 情绪走向（按时间轴给出 3~4 个节点，标注高/低点及触发事件）
2. 核心动机 & 痛点（各至少 2 条，用“动机-证据”或“痛点-证据”形式，证据指向原话并注明“来源：文件名#L行”）
3. 心理洞察 & 建议（结合产品定位，列出 2 条可执行建议，说明如何利用这些情绪信号优化体验）

格式要求：使用有序/无序列表，保证中文输出，并在结尾添加一句对用户情绪的共情总结。
```

### Step 2: 实现随机组卷算法

#### Hugo对AI说

```
请实现智能组卷算法，API路径 /api/papers/generate：

输入参数（从表单提交）:
- totalCount: 题目总数（如10）
- typeDistribution: { choice: 50, fillBlank: 30, qa: 20 }
- difficultyDistribution: { easy: 30, medium: 50, hard: 20 }
- knowledgePoints: ['有理数', '一元一次方程']

算法逻辑:
1. 根据题型分布计算每种题型需要的数量
   - 单选题: 10 * 50% = 5道
   - 填空题: 10 * 30% = 3道
   - 解答题: 10 * 20% = 2道

2. 根据难度分布计算每种难度需要的数量
   - 简单: 10 * 30% = 3道
   - 中等: 10 * 50% = 5道
   - 困难: 10 * 20% = 2道

3. 从questions表中查询符合条件的题目:
   - knowledge_points包含所选知识点（PostgreSQL数组查询）
   - created_by=当前用户 OR 从example_questions查询

4. 按题型和难度分组，随机抽取题目
   例如：先抽5道简单单选题中的2道，再抽5道中等单选题中的3道...

5. 如果题库数量不足，返回错误：'题库题目不足，请补充题目'

6. 生成试卷:
   - 创建papers表记录（name, created_by, created_at）
   - question_ids字段保存题目ID数组，如 [1, 5, 8, 12, ...]

7. 返回试卷ID

请提供完整的算法实现代码，包含详细注释。
```
