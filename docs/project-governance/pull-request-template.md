# Pull Request 模板（统一版）

> 在提交 PR 前，请复制以下结构到描述中，或直接引用本文件。所有勾选项使用 `[x]` / `[ ]`。若某项不适用，请写明原因（例如 “无新的环境变量”）。

---

## 1. 摘要
- **变更类型**：功能 / 修复 / 文档 / 架构 / 其他
- **核心目标**：1-2 句话说明为何提交本 PR
- **关联任务 / Issue**：可选，列出链接

## 2. 变更清单
- [ ] 涉及前端 UI 变更已附带截图或录屏
- [ ] 涉及后端/API 变更已更新接口说明
- [ ] 涉及文档迁移或新增，已同步索引（如 README / docs 目录）
- [ ] 涉及配置/脚本变更，已在 `.env.example` 或相关说明中更新
- [ ] 其他：_______

## 3. 自测结果
列出运行过的命令或脚本，例如：
```bash
npm run lint
npm run build
node scripts/run-image-baseline.mjs --limit 5
```
如有自动化测试，请补充测试结论或链接。

## 4. 风险与回滚
- **潜在风险**：如 UI 兼容、性能、权限等
- **回滚方案**：例如 `git revert <commit>` 或 “恢复旧配置并重新部署”

## 5. 审阅信息
- **需要 Review 的人/角色**：如 `@frontend-team @devops`
- **额外说明**：例如 “请关注 Tailwind 配色是否与 RealTime 主题一致”

---

> 若 PR 规模较大，建议在摘要部分附上“阶段性子任务”或“验证步骤链接”，便于 Review。
