# 文档管理与命名规范

## 1. 文档生命周期

1. **草稿阶段**:存放在个人分支或 `docs/project-governance/drafts/`(未公开)。
2. **生效阶段**:合入主分支后,必须在相关索引处登记,并注明"适用版本/日期"。
3. **归档阶段**:当内容被新的方案替代或失效时,迁移至 `docs/archive/...`,并在 `file-archive-log.md` 中记录。

## 2. 命名规则

- 统一使用 UTF-8,文件名推荐使用中划线或驼峰。中文名称允许但需在正文提供英文别名。
- 必须避免空格开头、特殊字符(`?`, `*`, `:`)和系统保留名(`nul`, `con` 等)。
- 版本号使用 `vX`/`vX.Y`,日期使用 `YYYY-MM-DD`。

示例:

| 类型 | 命名方式 |
| --- | --- |
| 阶段报告 | `phase3-usage-guide.md` |
| 运维手册 | `ops-health-checklist-2025-12.md` |
| 架构治理文档 | `project-status-tracker.md` |
| 归档资料 | `archive/legacy-plans/AI题库-数据库设计与Migration方案.md` |

## 3. 内容模板

所有文档建议包含以下段落:

1. **元数据**:`最后更新日期 / 适用范围 / 责任人`
2. **背景 & 目标**
3. **现状或差异**
4. **方案/步骤**
5. **验收标准或下一步**

## 4. 索引维护

- `docs/README.md`(后续需要补充)列出每一子目录用途。
- `documentation-handbook.md` 中附加"分类索引":

| 分类 | 文档 | 说明 |
| --- | --- | --- |
| 状态追踪 | `project-status-tracker.md` | 当前版本、阻塞、发布节奏 |
| 结构治理 | `project-structure-plan.md` | 目录与命名规范 |
| 现状分析 | `project-structure-status.md` | 最新扫描结果 |
| 归档记录 | `file-archive-log.md` | 文档/文件迁移清单 |

> 新增文档时,务必更新此索引。

## 5. 乱码与编码检查

- 在提交前执行 `rg "\\uFFFD" -n` 与 `rg "????(U+FFFD)" -n`,确认无损坏字符。
- 若发现旧文档存在乱码,优先修复内容或在归档说明中标注"需重新录入"。

## 6. 版本记录

- 重要文档在正文底部添加 `版本历史` 表,列出日期/修改内容。
- 重大变更需同步到 `project-status-tracker.md` 的"重大变更"段落。
