**POST /api/live-sessions/[id]/start-recording**

**功能**:
1. 验证用户身份和权限
2. 检查会话状态（必须是 live/scheduled）
3. 检查存储配额（预估 500MB/小时）
4. 调用 LiveKitAdapter.startRecording()
5. 返回 recordingId

**代码**:
```typescript
export async function POST(req: NextRequest, { params }: RouteParams) {
  // 1. 获取用户
  const user = await supabase.auth.getUser();

  // 2. 获取会话
  const session = await supabase.from('live_sessions').select('...').eq('id', sessionId).single();

  // 3. 权限检查
  if (session.created_by !== user.id) {
    return NextResponse.json({ error: 'Forbidden' }, { status: 403 });
  }

  // 4. 配额检查
  const quotaCheck = await quotaManager.checkAllQuotas(user.id, sessionId, estimatedSize);
  if (!quotaCheck.allowed) {
    return NextResponse.json({ error: quotaCheck.reason }, { status: 413 });
  }

  // 5. 开始录制
  const result = await livekit.startRecording({ sessionId, roomId, userId });
  return NextResponse.json({ recordingId: result.recordingId });
}
```

**POST /api/live-sessions/[id]/stop-recording**

**功能**:
1. 验证用户身份和权限
2. 调用 LiveKitAdapter.stopRecording()
3. 返回成功状态

- 组件卸载时自动清理

### 2. 实时时长计算
```typescript
// 基于 startedAt 计算时长
useEffect(() => {
  if (!status.isRecording || !status.startedAt) return;

  const updateElapsedTime = () => {
    const startTime = new Date(status.startedAt!).getTime();
    const elapsed = Math.floor((Date.now() - startTime) / 1000);
    setElapsedTime(elapsed);
  };

  updateElapsedTime();
  const interval = setInterval(updateElapsedTime, 1000);
  return () => clearInterval(interval);
}, [status.isRecording, status.startedAt]);
```

**优势**:
- 精确到秒
- 支持页面刷新后恢复
- 性能优化（仅录制时运行）

## 📝 笔记

### 设计决策

1. **为什么同时支持客户端和服务端录制？**
   - 客户端录制：低成本，适合个人留存
   - 服务端录制：高质量，适合官方存档

2. **为什么每 10 秒轮询而不是 WebSocket？**
   - 简单实现，无需额外基础设施
   - 10 秒延迟对录制状态可接受
   - 后期可升级为 WebSocket

3. **为什么配额预检查使用 500MB 估算？**
   - 基于 1080p, 3Mbps 录制
   - 1 小时 ≈ (3Mbps * 3600s) / 8 ≈ 1350MB
   - 保守估计 500MB/小时
