#### 1.1.3 添加自动重连机制（指数退避）
**文件**: [src/lib/connection-manager.ts](src/lib/live/connection-manager.ts:190-241)

**实现算法**:
```typescript
// 默认重试配置
{
  maxAttempts: 5,        // 最多重试 5 次
  baseDelay: 1000,       // 基础延迟 1 秒
  maxDelay: 30000,       // 最大延迟 30 秒
  backoffMultiplier: 2,  // 指数倍数 2
}

// 实际延迟计算（带随机抖动）
delay = min(baseDelay * 2^(attempt-1), maxDelay) ± 20%
```

**重连时序**:
```
尝试 1: ~1s 延迟
尝试 2: ~2s 延迟
尝试 3: ~4s 延迟
尝试 4: ~8s 延迟
尝试 5: ~16s 延迟
达到最大次数 → 停止重试，提示用户
```

**智能重连**:
- ✅ 自动判断错误是否可恢复
- ✅ Token 错误等不可恢复错误不会重试
- ✅ 连接成功后重置计数器
- ✅ 支持 ICE Restart（网络切换场景）

**效果**:
- 网络波动时自动恢复，减少用户干预
- 避免无意义的重试（如认证失败）
- 防止"惊群效应"（多客户端同时重连）

### 任务 1.2: 统一错误处理框架

#### 1.2.1 错误类型系统
**文件**: [src/lib/errors.ts](src/lib/errors.ts)

**定义的错误类型**:
```typescript
// 错误级别
enum ErrorLevel { INFO, WARNING, ERROR, CRITICAL }

// 错误类别
enum ErrorCategory {
  NETWORK, AUTH, VALIDATION, PERMISSION,
  NOT_FOUND, SERVER, CLIENT, UNKNOWN
}

// 标准错误接口
interface AppError {
  code: string;
  message: string;
  category: ErrorCategory;
  level: ErrorLevel;
  userMessage?: string;  // 用户友好消息
  recoverable?: boolean; // 是否可恢复
  timestamp: Date;
}
```

**预定义错误类**:
1. `NetworkError` - 网络连接错误
2. `AuthError` - 认证失败错误
3. `PermissionError` - 权限不足错误
4. `ValidationError` - 数据验证错误
5. `NotFoundError` - 资源未找到错误
6. `ServerError` - 服务器错误（5xx）

**错误处理函数**:
- `toAppError()` - 将任意错误转换为标准格式
- `handleApiError()` - 处理 HTTP 响应错误（根据状态码分类）
- `handleError()` - 全局错误处理入口
- `withErrorHandling()` - 包装异步函数，自动处理错误
- `withRetry()` - 错误重试包装器（支持自定义重试策略）

**示例用法**:
```typescript
// API 调用自动处理错误
const fetchData = withErrorHandling(async () => {
  const res = await fetch('/api/data');
  if (!res.ok) await handleApiError(res);
  return res.json();
});

// 带重试的 API 调用
const data = await withRetry(() => fetchData(), {
  maxAttempts: 3,
  delayMs: 1000,
});
```

**效果**:
- 统一的错误格式，便于日志收集和分析
- 自动转换技术错误为用户友好消息
- 支持错误重试，提升系统韧性

#### 1.2.2 日志系统
**文件**: [src/lib/logger.ts](src/lib/logger.ts)

**Logger 架构**:
```
Logger (单例)
  ├─ ConsoleTransport (开发环境)
  ├─ SupabaseTransport (生产环境)
  └─ 可扩展其他传输器（Sentry, LogRocket...）
```

**日志级别**:
```typescript
enum LogLevel {
  DEBUG,   // 调试信息
  INFO,    // 一般信息
  WARN,    // 警告
  ERROR,   // 错误
}
```

**核心功能**:
1. **日志缓冲和批量发送**
   - 警告和错误缓冲到 10 条或 5 秒后批量发送
   - 避免频繁网络请求

2. **上下文管理**
   - 全局上下文（用户ID、会话ID）
   - 局部上下文（通过 `child()` 创建）

3. **性能监控**
   - `PerformanceLogger` 类
   - 自动记录操作耗时
   - 支持检查点标记

**示例用法**:
```typescript
import { logger, PerformanceLogger } from '@/lib/logger';

// 普通日志
logger.info('User logged in', { userId: '123' });
logger.error('API call failed', error);

// 性能监控
const perfLogger = new PerformanceLogger('fetchUserData');
perfLogger.mark('start');
// ... 执行操作 ...
perfLogger.mark('completed');
perfLogger.end(true);
```

**效果**:
- 中心化的日志收集，便于问题排查
- 自动批量发送，降低性能影响
- 生产环境可对接第三方监控服务

## 📚 技术文档

### 架构图

```
┌──────────────────────────────────────────────┐
│           LiveKit Room Component             │
│  ┌────────────────────────────────────────┐  │
│  │     ConnectionStatusMonitor (UI)       │  │
│  │  ┌──────────────────────────────────┐  │  │
│  │  │   ConnectionManager (Logic)      │  │  │
│  │  │   - Status Monitoring            │  │  │
│  │  │   - Auto Reconnect               │  │  │
│  │  │   - Error Classification         │  │  │
│  │  └──────────────────────────────────┘  │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
                     │
                     ├─ Logger → Console/Supabase
                     ├─ Error Handler → Notifications
                     └─ ErrorBoundary → Fallback UI
```

### 调用流程

```typescript
// 1. LiveKit Room 初始化
<LiveKitRoom connectOptions={DEFAULT_CONNECT_OPTIONS}>

  // 2. ConnectionStatusMonitor 创建 ConnectionManager
  useEffect(() => {
    const manager = new ConnectionManager(room);
    manager.onStatusChange(setConnectionInfo);
  }, [room]);

  // 3. 连接状态变化 → 更新 UI
  ConnectionState.Connected
    → manager.handleConnectionStateChange()
    → updateStatus('connected')
    → notifyStatusCallbacks()
    → setConnectionInfo() // React state update
    → UI re-render

  // 4. 连接失败 → 自动重试
  Error
    → handleConnectionError()
    → toAppError() // 统一错误格式
    → logger.error() // 记录日志
    → shouldRetry() // 判断是否重试
    → scheduleReconnect() // 指数退避延迟
    → room.engine.reconnect() // ICE Restart
</LiveKitRoom>
```
