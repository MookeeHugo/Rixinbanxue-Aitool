## 🔍 问题排查过程

### 1. 初步分析
**初始怀疑**：用户ID `aaaaaaaa-1111-1111-1111-111111111111` 是占位符

**验证结果**：
- ✅ 用户ID是合法的测试账号（teacher@test.com）
- ✅ 数据库中存在对应的用户和数据
- ✅ 登录功能正常

**结论**：用户ID不是问题

### 2. 深入诊断
创建诊断脚本 `scripts/diagnose-auth.mjs` 进行详细测试。

**关键发现**：
```
❌ 查询classes失败: infinite recursion detected in policy for relation "classes"
错误代码: 42P17
```

### 3. 根本原因
**PostgreSQL RLS策略存在循环引用**，导致无限递归！

#### 循环链条

**classes表策略** (来自 `20241118000004_add_class_students.sql`):
```sql
-- 学生可以查看加入的班级
CREATE POLICY "Students can view joined classes"
  ON classes FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM class_students
      WHERE class_students.class_id = classes.id
        AND class_students.student_id = auth.uid()
    )
  );
```

**class_students表策略**:
```sql
-- 教师可以查看自己班级的学生
CREATE POLICY "Teachers can view own class students"
  ON class_students FOR SELECT
  USING (
    EXISTS (
      SELECT 1 FROM classes
      WHERE classes.id = class_students.class_id
        AND classes.teacher_id = auth.uid()
    )
  );
```

**递归过程**：
1. 查询 `classes` 表 → 触发 "Students can view joined classes" 策略
2. 策略需要查询 `class_students` → 触发 "Teachers can view own class students" 策略
3. 策略需要查询 `classes` → 回到步骤1
4. **无限循环** → PostgreSQL检测到递归 → 返回500错误

---

## ✅ 解决方案

### 方案：使用 SECURITY DEFINER 函数打破循环

创建 migration `20241120000001_fix_rls_infinite_recursion.sql`：

#### 1. 删除有问题的策略
```sql
DROP POLICY IF EXISTS "Teachers can view own class students" ON class_students;
DROP POLICY IF EXISTS "Teachers can remove students from own classes" ON class_students;
DROP POLICY IF EXISTS "Students can view joined classes" ON classes;
DROP POLICY IF EXISTS "Students can view class assignments" ON assignments;
```

#### 2. 创建 SECURITY DEFINER 辅助函数
```sql
-- 检查用户是否是班级的教师（绕过 RLS）
CREATE OR REPLACE FUNCTION is_class_teacher(class_uuid UUID, user_uuid UUID)
RETURNS BOOLEAN
LANGUAGE SQL
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1 FROM classes
    WHERE id = class_uuid AND teacher_id = user_uuid
  );
$$;

-- 检查学生是否在班级中（绕过 RLS）
CREATE OR REPLACE FUNCTION is_student_in_class(class_uuid UUID, user_uuid UUID)
RETURNS BOOLEAN
LANGUAGE SQL
SECURITY DEFINER
SET search_path = public
AS $$
  SELECT EXISTS (
    SELECT 1 FROM class_students
    WHERE class_id = class_uuid AND student_id = user_uuid
  );
$$;
```

**关键点**：`SECURITY DEFINER` 函数在执行时**绕过RLS检查**，打破了循环引用。

#### 3. 重新创建策略（使用辅助函数）
```sql
-- class_students: 教师可以查看自己班级的学生
CREATE POLICY "Teachers can view own class students"
  ON class_students FOR SELECT
  USING (is_class_teacher(class_id, auth.uid()));

-- classes: 学生可以查看自己加入的班级
CREATE POLICY "Students can view joined classes"
  ON classes FOR SELECT
  USING (is_student_in_class(id, auth.uid()));

-- assignments: 学生可以查看自己班级的作业
CREATE POLICY "Students can view class assignments"
  ON assignments FOR SELECT
  USING (is_student_in_class(class_id, auth.uid()));
```

## 🎓 知识总结

### PostgreSQL RLS最佳实践

1. **避免策略循环引用**
   - 表A的策略不应该查询表B，如果表B的策略也查询表A

2. **使用 SECURITY DEFINER 函数**
   - 当需要跨表查询时，使用辅助函数绕过RLS检查
   - 函数内部的查询不会触发RLS策略

3. **策略设计原则**
   - 尽量使用简单的列比较（如 `user_id = auth.uid()`）
   - 复杂的权限检查使用辅助函数
   - 避免深层嵌套的 EXISTS 子查询

4. **诊断工具**
   - 创建测试脚本验证策略正确性
   - 使用 `EXPLAIN` 查看查询计划
   - 检查 PostgreSQL 日志中的递归错误

### RLS递归错误识别

**错误特征**：
```
ERROR: infinite recursion detected in policy for relation "table_name"
SQLSTATE: 42P17
HTTP Status: 500
```

**排查步骤**：
1. 查看涉及表的所有RLS策略
2. 绘制策略引用关系图
3. 识别循环引用链
4. 使用 SECURITY DEFINER 函数打破循环
