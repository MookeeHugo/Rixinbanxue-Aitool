## 🔴 高优先级修复详情

### 1. src/app/questions/page.tsx - 4个问题 ✅

**文件重要性**: 题库管理页面，用户使用频率最高的核心功能

**修复内容**:

#### 1.1 highlightMatch 函数优化
- **问题**: 搜索高亮函数每次渲染都重新创建，在表格数据渲染时频繁调用
- **影响**: 性能影响大，表格每行都调用此函数
- **修复**: 使用 `useCallback` 包裹，依赖项 `[searchText]`
- **代码变化**:
  ```typescript
  // Before
  const highlightMatch = (text: string) => { ... }

  // After
  const highlightMatch = useCallback((text: string) => { ... }, [searchText])
  ```

#### 1.2 事件处理函数优化（8个函数）
- **修复函数列表**:
  1. `handleAddToBasketAction` - 依赖项: `[hasQuestionInBasket, addToBasket]`
  2. `handleStartBuildFromBasket` - 依赖项: `[basketQuestions, router]`
  3. `handleExportFromBasket` - 依赖项: `[basketQuestions]`
  4. `callDeleteApi` - 依赖项: `[questionMap]`
  5. `handleDelete` - 依赖项: `[]`
  6. `handleBulkDelete` - 依赖项: `[selectedRowKeys, deleteMode, callDeleteApi]`
  7. `handleBulkExport` - 依赖项: `[selectedRowKeys, questionMap]`
  8. `handleBulkImport` - 依赖项: `[profile]`

- **影响**: 避免每次渲染重新创建函数，减少子组件不必要的重渲染
- **性能提升**: 按钮点击响应更快，表格渲染效率提高

#### 1.3 columns 配置优化
- **问题**: Table 的 columns 配置每次渲染都重新创建，导致 Table 组件不必要的重渲染
- **影响**: 性能影响大，Table 会因为 columns 引用变化而完全重新渲染
- **修复**: 使用 `useMemo` 包裹，依赖项 `[highlightMatch, hasQuestionInBasket, handleAddToBasketAction, handleDelete]`
- **性能提升**: Table 仅在依赖项变化时重新渲染

#### 1.4 rowSelection 对象优化
- **问题**: rowSelection 对象每次渲染都重新创建
- **影响**: Table 组件会因为 rowSelection 引用变化而重新渲染
- **修复**: 使用 `useMemo` 包裹，依赖项 `[selectedRowKeys]`

**修复结果**: ✅ 成功，无TypeScript错误

### 2. src/app/papers/create/page.tsx - 2个问题 ✅

**文件重要性**: 组卷功能，教师核心业务流程

**修复内容**:

#### 2.1 事件处理函数批量优化（10个函数）
- **修复函数列表**:
  1. `toggleKnowledgePoint` - 使用函数式 setState，无需依赖
  2. `addRequirement` - 使用函数式 setState，无需依赖
  3. `removeRequirement` - 使用函数式 setState，无需依赖
  4. `updateRequirement` - 使用函数式 setState，无需依赖
  5. `generatePaper` - 依赖项: `[paperName, requirements, selectedKnowledgePoints]`
  6. `savePaper` - 依赖项: `[selectedQuestions, paperName, user, router]`
  7. `getTotalQuestions` - 依赖项: `[requirements]`
  8. `removeQuestion` - 使用函数式 setState，无需依赖
  9. `moveQuestionUp` - 使用函数式 setState，无需依赖
  10. `moveQuestionDown` - 使用函数式 setState，无需依赖

- **优化亮点**: 大量使用函数式 setState `(prev => ...)` 模式，最小化依赖数组
- **性能提升**: 组卷界面交互更流畅，状态更新更高效

#### 2.2 知识点过滤优化
- **问题**: `knowledgePoints.filter()` 操作每次渲染都执行
- **影响**: 当知识点列表较长时，filter 操作影响性能
- **修复**: 添加 `useMemo` 缓存过滤结果
  ```typescript
  const filteredKnowledgePoints = useMemo(
    () => knowledgePoints.filter(point => point.includes(searchTerm)),
    [knowledgePoints, searchTerm]
  )
  ```

**修复结果**: ✅ 成功，无TypeScript错误

### 3. src/app/assignments/page.tsx - 2个问题 ✅

**文件重要性**: 作业列表页面，教师端核心功能

**修复内容**:

#### 3.1 useCallback 依赖项优化
- **问题**: `deleteAssignment` 函数依赖数组包含 `assignments`，但内部使用函数式 setState 不需要此依赖
- **影响**: 每次 assignments 更新都会重新创建函数，失去 useCallback 的意义
- **修复**: 移除 assignments 依赖
  ```typescript
  // Before
  const deleteAssignment = useCallback(async (id: string) => {
    setAssignments(prev => prev.filter(...))
  }, [assignments])  // ❌ 不必要的依赖

  // After
  const deleteAssignment = useCallback(async (id: string) => {
    setAssignments(prev => prev.filter(...))
  }, [])  // ✅ 无需依赖
  ```

#### 3.2 纯函数外移
- **问题**: `getStatusColor` 和 `getStatusText` 两个纯函数在组件内部定义，每次渲染都重新创建
- **影响**: 在 map 循环中被调用，导致不必要的函数重新创建
- **修复**: 移到组件外部定义
  ```typescript
  // 在组件外部（文件顶部）
  function getStatusColor(status: string) {
    const colors: Record<string, string> = {
      draft: 'gray',
      published: 'blue',
      archived: 'orange'
    }
    return colors[status] || 'default'
  }

  function getStatusText(status: string) {
    const texts: Record<string, string> = {
      draft: '草稿',
      published: '已发布',
      archived: '已归档'
    }
    return texts[status] || status
  }
  ```

**修复结果**: ✅ 成功，无TypeScript错误

## 🎯 最佳实践总结

### ✅ 应该做的

1. **函数式 setState 优先**
   ```typescript
   // ✅ Good
   setState(prev => ...)  // 无需依赖state

   // ❌ Bad
   setState(state + 1)  // 需要依赖state
   ```

2. **纯函数外移**
   ```typescript
   // ✅ Good - 组件外部
   function getTypeLabel(type: string) { ... }

   // ❌ Bad - 组件内部
   const MyComponent = () => {
     const getTypeLabel = (type: string) => { ... }
   }
   ```

3. **最小化依赖数组**
   ```typescript
   // ✅ Good
   const handler = useCallback(() => {
     setState(prev => ({ ...prev, active: true }))
   }, [])  // 无依赖

   // ❌ Bad
   const handler = useCallback(() => {
     setState({ ...state, active: true })
   }, [state])  // 不必要的依赖
   ```

4. **配置对象使用 useMemo**
   ```typescript
   // ✅ Good
   const columns = useMemo(() => [...], [deps])

   // ❌ Bad
   const columns = [...]  // 每次渲染重新创建
   ```

### ❌ 不应该做的

1. ❌ 过度优化：简单的计算不需要 useMemo
2. ❌ 遗漏依赖项：必须包含所有使用的外部变量
3. ❌ 滥用 useCallback：不作为 props 传递的函数可以不优化
4. ❌ 依赖对象/数组：应该依赖具体的原始值
