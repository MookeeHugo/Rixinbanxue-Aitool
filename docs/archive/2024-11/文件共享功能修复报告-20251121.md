# 文件共享功能修复报告 - 2025年11月21日

## 📋 问题概述

在实现直播文件共享功能后，出现了严重的内存溢出错误，导致页面崩溃：

```
RangeError: Failed to execute 'getImageData' on 'CanvasRenderingContext2D': Out of memory at ImageData creation
```

同时还伴随着：
- 重复的图片加载失败错误
- LiveKit 连接不稳定，容易崩溃
- 页面频繁刷新和重新渲染

##  根本原因分析

### 1. 内存溢出的根本原因

在 `Whiteboard.tsx` 的第 153 行，`displayedImage` useEffect 的依赖数组中包含了 `historyStep`：

```typescript
useEffect(() => {
  // ... 图片加载代码 ...

  img.onload = () => {
    // ... 绘制图片 ...

    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
    setHistory((prev) => {
      const newHistory = prev.slice(0, historyStep + 1);
      newHistory.push(imageData);
      // ...
      setHistoryStep((step) => step + 1); // 🚨 触发状态更新
    });
  };
}, [displayedImage, historyStep]); // 🚨 historyStep 作为依赖
```

**无限循环的形成过程：**

1. 用户点击"在白板上显示"→ `displayedImage` 变化
2. useEffect 触发，开始加载图片
3. 图片加载完成，调用 `getImageData`（分配约 8MB 内存）
4. 更新 `historyStep` 状态
5. **`historyStep` 变化触发 useEffect 重新执行**
6. 再次加载图片，再次调用 `getImageData`（再分配 8MB）
7. 再次更新 `historyStep`...
8. **循环往复，浏览器内存耗尽**

### 2. 其他问题

- **数据库迁移错误**：引用了不存在的 `users` 表，应该是 `auth.users`
- **RLS 策略错误**：引用了不存在的字段
- **Supabase 客户端导入错误**：错误使用了 `createClient` 而不是导入单例实例
- **LiveKit 连接稳定性**：缺少重连策略和错误处理

## ✅ 已实施的修复

### 1. 修复内存溢出 Bug（核心修复）

**文件**：`src/components/live/Whiteboard.tsx`

**修改前**：
```typescript
useEffect(() => {
  // ... 加载代码 ...

  img.onload = () => {
    const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
    setHistory((prev) => {
      const newHistory = prev.slice(0, historyStep + 1);
      newHistory.push(imageData);
      // ...
    });
  };
}, [displayedImage, historyStep]); // ❌ 导致无限循环
```

**修改后**：
```typescript
useEffect(() => {
  if (!displayedImage || typeof displayedImage !== 'string' || displayedImage.trim() === '') {
    return;
  }

  const canvas = canvasRef.current;
  if (!canvas) return;
  const ctx = canvas.getContext("2d");
  if (!ctx) return;

  const img = new Image();
  let isActive = true; // ✅ 添加清理标志

  img.onload = () => {
    if (!isActive) return; // ✅ 防止组件卸载后执行

    // ... 绘制图片 ...

    // ✅ 使用 try-catch 防止内存溢出崩溃
    try {
      const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
      setHistory((prev) => {
        const newHistory = [...prev, imageData]; // ✅ 简化逻辑
        if (newHistory.length > 50) {
          newHistory.shift();
          return newHistory;
        }
        return newHistory;
      });
      setHistoryStep((prev) => Math.min(prev + 1, 49)); // ✅ 使用函数式更新
    } catch (e) {
      console.error('保存图片到历史记录失败:', e);
    }
  };

  img.src = displayedImage;

  return () => {
    isActive = false; // ✅ 清理函数
  };
}, [displayedImage]); // ✅ 只依赖 displayedImage，打破循环
```

**关键改进**：
1. ✅ **移除 `historyStep` 依赖**：打破无限循环
2. ✅ **添加 `isActive` 标志**：防止组件卸载后继续执行
3. ✅ **添加清理函数**：组件卸载时设置 `isActive = false`
4. ✅ **使用函数式状态更新**：不需要在依赖中包含 `historyStep`
5. ✅ **添加 try-catch**：防止 `getImageData` 错误导致页面崩溃

### 5. 增强 LiveKit 连接稳定性

**文件**：`src/components/live/LiveRoomProvider.tsx`

**添加的配置**：
```typescript
<LiveKitRoom
  options={{
    // ✅ 添加重连策略
    reconnectPolicy: {
      nextRetryDelayInMs: (context) => {
        if (context.retryCount >= 5) return null; // 最多重试5次
        return Math.min(1000 * Math.pow(2, context.retryCount), 10000);
      },
    },
    // ✅ 页面切换时不断开连接
    disconnectOnPageLeave: false,
  }}
  // ✅ 改进错误处理
  onError={(error) => {
    console.error('LiveKit 连接错误:', error);
    setError(`连接错误: ${error.message}`); // 不自动跳转
  }}
/>
```

## 🎯 技术要点总结

### React Hooks 最佳实践

1. **依赖数组管理**：
   - ❌ 避免将状态变量作为依赖，如果该状态在 effect 中被更新
   - ✅ 使用函数式状态更新：`setState(prev => ...)`

2. **清理函数**：
   - ✅ 异步操作前设置 `isActive` 标志
   - ✅ 在清理函数中设置 `isActive = false`
   - ✅ 在异步回调中检查 `if (!isActive) return`

3. **错误处理**：
   - ✅ 对可能失败的操作（如 `getImageData`）使用 try-catch
   - ✅ 提供降级方案而不是让页面崩溃

### Canvas 性能优化

1. **ImageData 内存管理**：
   - 1920x1080 canvas → 每次 `getImageData` 约 8MB
   - ✅ 限制历史记录数量（最多 50 个）
   - ✅ 使用环形缓冲区（删除最旧的记录）
   - ✅ 避免不必要的 `getImageData` 调用

2. **防止内存泄漏**：
   - ✅ Image 对象在加载完成后会被垃圾回收
   - ✅ 清理函数确保不会在组件卸载后继续执行
