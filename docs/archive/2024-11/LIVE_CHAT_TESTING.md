
```bash

```

确保本地Supabase正在运行：


## 🔧 故障排查

### 问题1：消息不实时更新

**症状**：发送消息后，其他窗口看不到新消息

**解决方案**：

1. 检查Supabase Realtime是否启用
   ```bash
   # 访问Supabase Studio
   http://localhost:54323

   # 检查 Database > Replication
   # 确保 live_chat_messages 表已启用 Realtime
   ```

2. 检查浏览器控制台错误
   - 查看是否有 WebSocket 连接错误
   - 查看是否有 RLS 权限错误

3. 检查RLS策略
   ```sql
   -- 在Supabase SQL Editor执行
   SELECT * FROM pg_policies WHERE tablename = 'live_chat_messages';
   ```

### 问题2：无法发送消息

**症状**：点击发送按钮没有反应

**解决方案**：

1. 检查浏览器控制台错误
2. 检查API响应：
   ```
   Network > XHR > /api/live-sessions/[id]/messages
   ```
3. 检查用户是否已登录
4. 检查RLS策略是否正确

### 问题3：聊天面板不显示

**症状**：进入课堂后只看到视频，没有聊天面板

**解决方案**：

1. 确保已点击"进入课堂"按钮
2. 检查浏览器窗口宽度
   - 在小屏幕上，聊天面板可能在视频下方
   - 尝试调整浏览器窗口大小
3. 检查浏览器控制台是否有React错误

### 问题4：消息历史加载失败

**症状**：刷新后看不到之前的消息

**解决方案**：

1. 检查API响应：
   ```
   GET /api/live-sessions/[id]/messages
   ```
2. 检查数据库中是否有数据：
   ```sql
   SELECT * FROM live_chat_messages WHERE session_id = 'your-session-id';
   ```
3. 检查RLS SELECT策略

## 💡 技术实现说明

### 数据库表结构
```sql
CREATE TABLE live_chat_messages (
  id UUID PRIMARY KEY,
  session_id UUID REFERENCES live_sessions(id),
  user_id UUID REFERENCES profiles(id),
  message TEXT NOT NULL,
  message_type TEXT DEFAULT 'text',
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### API端点
- `GET /api/live-sessions/[id]/messages` - 获取历史消息
- `POST /api/live-sessions/[id]/messages` - 发送新消息

### Realtime订阅
```typescript
supabase
  .channel(`live_chat:${sessionId}`)
  .on('postgres_changes', {
    event: 'INSERT',
    schema: 'public',
    table: 'live_chat_messages',
    filter: `session_id=eq.${sessionId}`
  }, handleNewMessage)
  .subscribe();
```
