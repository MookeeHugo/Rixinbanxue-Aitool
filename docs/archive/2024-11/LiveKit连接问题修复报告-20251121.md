# LiveKit 连接问题修复报告

## 📅 修复时间
2025-11-21

## ❌ 原始问题

### 错误信息
```
ConnectionError: could not establish pc connection
Maximum update depth exceeded (Whiteboard 组件)
```

### 症状
1. LiveKit WebRTC 连接失败
2. 浏览器控制台显示 "could not establish pc connection"
3. Whiteboard 组件无限循环崩溃
4. 直播间无法正常使用

## 🔍 问题分析

### 1. LiveKit 连接问题

从 LiveKit 日志分析发现：

```json
{
  "state": "failed",
  "nominated": false,
  "requestsSent": 8,
  "responsesReceived": 0
}
```

**根本原因**：
- LiveKit 运行在 Docker 容器中（`172.19.0.2`）
- 默认配置尝试使用公网 STUN 服务器
- 本地开发环境无法正确建立 NAT 穿透
- 所有 ICE 候选对都失败，0 个响应

**技术细节**：
```
Publisher ICE Candidates:
- [local] 172.19.0.2:7882 (Docker 内部 IP)
- [remote] 38.90.18.x:xxxxx (公网 IP)
❌ 无法连接：Docker bridge 网络隔离

Subscriber ICE Candidates:
- 同样的问题
```

### 2. Whiteboard 组件问题

**错误位置**：[src/components/live/Whiteboard.tsx](src/components/live/Whiteboard.tsx:73-88)

**原因**：
```typescript
// 错误的代码
useEffect(() => {
  saveToHistory();  // ❌ 依赖 saveToHistory
}, [saveToHistory]);  // ❌ saveToHistory 每次都变化
```

**触发链**：
1. `useEffect` 调用 `saveToHistory()`
2. `saveToHistory()` 依赖 `history` 和 `historyStep`
3. `saveToHistory()` 更新 `history` 和 `historyStep`
4. 状态更新导致组件重渲染
5. `saveToHistory` 函数引用改变
6. `useEffect` 再次触发 → 无限循环

## ✅ 解决方案

### 1. LiveKit 配置修复

#### 创建本地开发配置 ([livekit.yaml](livekit.yaml))

```yaml
# 关键配置
rtc:
  use_external_ip: false
  node_ip: "127.0.0.1"

  # 仅使用本地 ICE 候选
  ice_servers:
    - urls:
        - "stun:localhost:7882"

  # 禁用 TCP fallback
  allow_tcp_fallback: false

# 开发模式
development: true
```

**关键改动**：
- ✅ 使用本地 IP（127.0.0.1）
- ✅ 禁用外部 STUN 服务器
- ✅ 使用主机网络模式

#### 更新 Docker Compose ([docker-compose.livekit.yml](docker-compose.livekit.yml))

```yaml
services:
  livekit:
    # 使用主机网络模式（重要！）
    network_mode: "host"

    # 指定配置文件
    command: --config /etc/livekit.yaml --node-ip 127.0.0.1

    volumes:
      - ./livekit.yaml:/etc/livekit.yaml:ro
```

**为什么使用 `host` 网络模式？**
- Docker bridge 网络会隔离容器
- WebRTC 需要直接访问本地网络接口
- `host` 模式让容器使用主机网络栈
- 避免 NAT 穿透问题

### 2. Whiteboard 组件修复

#### 修复无限循环 ([src/components/live/Whiteboard.tsx](src/components/live/Whiteboard.tsx:73-88))

```typescript
// ✅ 修复后的代码
useEffect(() => {
  const canvas = canvasRef.current;
  if (!canvas) return;

  const ctx = canvas.getContext("2d", { willReadFrequently: true });
  if (!ctx) return;

  // 设置画布背景
  ctx.fillStyle = "#0f172a";
  ctx.fillRect(0, 0, canvas.width, canvas.height);

  // 直接保存，不调用 saveToHistory()
  const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
  setHistory([imageData]);
  setHistoryStep(0);
}, []); // ✅ 空依赖数组 - 只运行一次
```

**修复要点**：
1. 移除 `saveToHistory` 依赖
2. 使用空依赖数组 `[]`
3. 直接内联初始化逻辑
4. 添加 `willReadFrequently: true`（性能优化）

#### 修复 Canvas 性能警告

```typescript
// 所有 getContext 调用添加性能提示
const ctx = canvas.getContext("2d", { willReadFrequently: true });
```

**作用**：告诉浏览器这个 canvas 会频繁读取（`getImageData`），优化渲染性能。

## 🔧 技术细节

### WebRTC ICE 连接流程

```
1. 收集 ICE 候选（Candidates）
   ├─ Host: 本地网络接口
   ├─ Srflx: STUN 服务器反射地址
   └─ Relay: TURN 服务器中继

2. 交换候选（通过信令服务器）

3. 连接检查（Connectivity Checks）
   ├─ 发送 STUN 请求
   ├─ 接收 STUN 响应
   └─ 建立候选对

4. 选择最佳候选对
   └─ 根据优先级和延迟

5. 建立媒体连接
```

**本地开发问题**：
- Docker bridge 网络 → Host 候选不可达
- 公网 STUN → Srflx 候选在本地无意义
- 防火墙/NAT → 连接失败

**解决方案**：
- 使用 `host` 网络模式
- 禁用外部 STUN
- 直接使用本地 IP

### React Hook 依赖问题

```
useCallback/useMemo 依赖陷阱：

function Component() {
  const [state, setState] = useState(0);

  // ❌ 问题：依赖 state
  const fn = useCallback(() => {
    setState(state + 1);  // 使用旧的 state
  }, [state]);  // state 变化 → fn 变化

  // ❌ 问题：依赖 fn
  useEffect(() => {
    fn();  // 调用 fn → 更新 state → fn 变化 → 循环
  }, [fn]);
}

解决方案：

1. 使用函数式更新
   setState(prev => prev + 1);  // ✅ 不依赖 state

2. 减少依赖
   useEffect(() => {
     // 直接写逻辑
   }, []);  // ✅ 空依赖

3. 使用 ref
   const fnRef = useRef();
   fnRef.current = fn;  // ✅ ref 不触发重渲染
```

## ⚠️ 注意事项

### 1. 生产环境配置

**本配置仅适用于本地开发！**

生产环境需要：
- ✅ 使用真实的公网 IP
- ✅ 配置 STUN/TURN 服务器
- ✅ 使用 HTTPS/WSS
- ✅ 配置防火墙规则
- ✅ 负载均衡和高可用

### 2. Windows/Mac 差异

- **Linux**: `network_mode: "host"` 完美支持
- **Windows/Mac**: Docker Desktop 使用虚拟机，`host` 模式有限制
  - 可能需要额外配置端口映射
  - 或使用其他网络方案

### 3. 防火墙配置

确保以下端口开放：
- `7880` - WebRTC WebSocket
- `7881` - HTTP API
- `7882/udp` - TURN/UDP（如果使用）
