## 🔍 问题 1：Supabase 登录态问题深度分析

### 问题现象

```
现象：本地 Supabase /auth/v1/token 返回 200，但响应头无 Set-Cookie
结果：
- ✅ 前端 localStorage 有 session (sb-127-auth-token)
- ❌ 浏览器 cookies 为空
- ❌ Next.js SSR/middleware 无法读取登录态
- ❌ E2E 测试登录后仍停留在 /login 页面
```

### 根本原因分析

#### 1.1 本地 Supabase 认证机制
```
本地 Supabase Auth 与云端不同：
- 云端：返回 Set-Cookie 响应头，自动设置 HttpOnly cookie
- 本地：仅返回 JSON body，不包含 Set-Cookie
- 原因：本地 Supabase (supabase-demo) 未配置 cookie 域名
```

#### 1.2 Next.js 鉴权链路断裂
```mermaid
用户登录
  ↓
Supabase Auth API (无 Set-Cookie)
  ↓
前端获取 session → 存入 localStorage
  ↓
调用 /api/auth/set-session 写入 cookie (尝试修复)
  ↓
❌ 但该 API 返回的 Set-Cookie 也未生效
  ↓
middleware.ts 读取 cookies → 空 → 重定向到 /login
```

#### 1.3 已尝试的修复方案（均失败）
- ✗ 硬编码本地 Supabase 配置
- ✗ 使用 127.0.0.1 对齐域名
- ✗ 手动注入 `sb-127-auth-token` cookie
- ✗ 创建 `/api/auth/set-session` API 手动写入
- ✗ 启用 PKCE 流程
- ✗ 在 login 页面调用 set-session API

### 为什么 `/api/auth/set-session` 无效？

**代码审查发现：**
```typescript
// src/app/api/auth/set-session/route.ts:35
res.headers.append(
  'Set-Cookie',
  `${COOKIE_NAME}=${cookieValue}; Path=/; HttpOnly; SameSite=Lax`
)
```

**问题分析：**
1. 缺少 `Domain` 属性 → 可能被浏览器拒绝
2. `SameSite=Lax` 在某些情况下可能不够
3. Next.js 13+ App Router 的 cookie 设置需要使用 `cookies()` 而非 headers.append

## ✅ 问题 1 解决方案

### 方案 A：修复服务端 Cookie 写入（推荐）

#### A1. 修改 `/api/auth/set-session` 使用 Next.js cookies API

**实施步骤：**

```typescript
// src/app/api/auth/set-session/route.ts
import { cookies } from 'next/headers'
import { NextResponse } from 'next/server'

export async function POST(req: Request) {
  try {
    const body = await req.json()
    const { access_token, refresh_token, expires_at } = body

    if (!access_token || !refresh_token || !expires_at) {
      return NextResponse.json({ error: '缺少必要字段' }, { status: 400 })
    }

    // 使用 Next.js cookies API（更可靠）
    const cookieStore = await cookies()
    const sessionData = JSON.stringify({
      access_token,
      refresh_token,
      expires_at,
      token_type: 'bearer',
    })

    // 方法 1：使用 Supabase 标准 cookie 格式
    cookieStore.set('sb-127-auth-token', sessionData, {
      path: '/',
      httpOnly: true,
      sameSite: 'lax',
      secure: false, // 本地开发使用 http
      maxAge: 60 * 60 * 24 * 7, // 7 天
    })

    // 方法 2：同时设置项目特定 cookie（兼容性）
    cookieStore.set('sb-Rixindemo-codex-m1-auth-token', sessionData, {
      path: '/',
      httpOnly: true,
      sameSite: 'lax',
      secure: false,
      maxAge: 60 * 60 * 24 * 7,
    })

    console.log('[set-session] ✅ Cookie 设置成功')
    return NextResponse.json({ ok: true })
  } catch (error) {
    console.error('[set-session] error', error)
    return NextResponse.json({ error: '设置 session 失败' }, { status: 500 })
  }
}
```

**优点：**
- 使用 Next.js 官方 API，兼容性最好
- 支持 App Router
- cookie 设置更可靠

**缺点：**
- 需要修改现有代码

#### A2. 创建 Middleware 自动同步 localStorage → Cookie

**原理：** 让 middleware 检测 localStorage session 并自动写入 cookie

**实施步骤：**

```typescript
// src/middleware.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export async function middleware(request: NextRequest) {
  const response = NextResponse.next()

  // 从请求头获取 localStorage session（需要客户端配合）
  const sessionHeader = request.headers.get('x-supabase-session')

  if (sessionHeader) {
    // 自动设置 cookie
    response.cookies.set('sb-127-auth-token', sessionHeader, {
      httpOnly: true,
      sameSite: 'lax',
      path: '/',
      maxAge: 60 * 60 * 24 * 7,
    })
  }

  // 检查是否有认证 cookie
  const authCookie = request.cookies.get('sb-127-auth-token')
  const isLoginPage = request.nextUrl.pathname.startsWith('/login')
  const isRegisterPage = request.nextUrl.pathname.startsWith('/register')
  const isPublicPage = isLoginPage || isRegisterPage

  // 已登录用户访问登录/注册页 → 重定向到首页
  if (isPublicPage && authCookie) {
    return NextResponse.redirect(new URL('/', request.url))
  }

  // 未登录用户访问受保护页面 → 重定向到登录页
  if (!isPublicPage && !authCookie) {
    // 除了首页、调试页面等公开页面
    const publicPaths = ['/', '/debug-env']
    if (!publicPaths.includes(request.nextUrl.pathname)) {
      return NextResponse.redirect(new URL('/login', request.url))
    }
  }

  return response
}

export const config = {
  matcher: [
    '/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)',
  ],
}
```

**客户端配合：**
```typescript
// src/lib/supabase.ts
import { createClient } from '@supabase/supabase-js'

export const supabase = createClient(supabaseUrl, supabaseAnonKey, {
  auth: {
    flowType: 'pkce',
    autoRefreshToken: true,
    persistSession: true,
    detectSessionInUrl: true,
    storageKey: 'sb-auth',
  },
  global: {
    headers: {
      // 在每个请求中携带 session
      get 'x-supabase-session'() {
        if (typeof window !== 'undefined') {
          return localStorage.getItem('sb-127-auth-token') || ''
        }
        return ''
      },
    },
  },
})
```

### 方案 B：完全基于 localStorage 的客户端认证（临时方案）

**适用场景：** 开发阶段，不依赖 SSR 鉴权

**实施步骤：**

1. **移除 middleware 鉴权依赖**
2. **改为客户端 useEffect 检查登录态**
3. **延迟 SSR 鉴权到生产环境**

```typescript
// src/components/ClientAuthGuard.tsx
'use client'

import { useEffect, useState } from 'react'
import { useRouter } from 'next/navigation'
import { supabase } from '@/lib/supabase'

export function ClientAuthGuard({ children }: { children: React.ReactNode }) {
  const router = useRouter()
  const [isAuthenticated, setIsAuthenticated] = useState<boolean | null>(null)

  useEffect(() => {
    checkAuth()

    // 监听 auth 状态变化
    const { data: { subscription } } = supabase.auth.onAuthStateChange((event, session) => {
      setIsAuthenticated(!!session)

      if (event === 'SIGNED_OUT') {
        router.push('/login')
      }
    })

    return () => subscription.unsubscribe()
  }, [router])

  async function checkAuth() {
    const { data: { session } } = await supabase.auth.getSession()
    setIsAuthenticated(!!session)

    if (!session && !isPublicPage()) {
      router.push('/login')
    }
  }

  function isPublicPage() {
    const pathname = window.location.pathname
    return ['/', '/login', '/register', '/debug-env'].includes(pathname)
  }

  // 加载中显示占位符
  if (isAuthenticated === null) {
    return <div className="flex items-center justify-center min-h-screen">加载中...</div>
  }

  return <>{children}</>
}
```

**优点：**
- 简单快速，立即可用
- 不依赖 cookie

**缺点：**
- 无法使用 SSR 鉴权
- 首次加载会闪烁
- SEO 不友好

```typescript
export async function middleware(req: NextRequest) {

    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_ANON_KEY!,

  return res
```

## 🔍 问题 2：Playwright E2E 测试环境不稳定

### 问题现象
```
- dev 服务器启动后可能无法稳定访问 /questions
- .auth 存档失效概率高
- auth.setup.ts 期望登录后跳转到 /questions，但实际可能停留在首页
- 需要手动启动 dev 和 supabase 服务
```

### 根本原因分析

#### 2.1 auth.setup.ts 假设错误
```typescript
// tests/e2e/auth.setup.ts:26
await page.waitForURL('**/questions', { waitUntil: 'domcontentloaded', timeout: 60000 })
```

**问题：** 登录成功后不一定跳转到 `/questions`，实际跳转到 `/`（首页）

#### 2.2 dev 服务器启动时机
- globalSetup 在所有测试前运行
- 但此时 dev 服务器可能尚未就绪
- 导致 auth 初始化失败

#### 2.3 storageState 过期问题
- localStorage 中的 access_token 有效期 1小时
- 如果测试间隔超过 1小时，auth 失效
- 需要重新登录

## ✅ 问题 2 解决方案

### 方案 A：修复 auth.setup.ts 逻辑

```typescript
// tests/e2e/auth.setup.ts
import { chromium, type FullConfig } from '@playwright/test'
import fs from 'node:fs'
import path from 'node:path'

const AUTH_DIR = path.join(process.cwd(), 'playwright/.auth')

interface Account {
  name: string
  email: string
  password: string
  statePath: string
}

async function waitForDevServer(baseURL: string, maxRetries = 30) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(baseURL)
      if (response.ok) {
        console.log(`✅ Dev server is ready at ${baseURL}`)
        return
      }
    } catch (error) {
      console.log(`⏳ Waiting for dev server... (${i + 1}/${maxRetries})`)
      await new Promise(resolve => setTimeout(resolve, 1000))
    }
  }
  throw new Error(`❌ Dev server not ready after ${maxRetries} attempts`)
}

async function ensureAuthState(baseURL: string, account: Account) {
  // 检查是否已有有效的 auth state
  if (fs.existsSync(account.statePath)) {
    try {
      const authState = JSON.parse(fs.readFileSync(account.statePath, 'utf-8'))
      const origins = authState.origins || []
      const localStorage = origins[0]?.localStorage || []
      const sessionItem = localStorage.find((item: any) =>
        item.name.includes('auth-token') || item.name === 'sb-auth'
      )

      if (sessionItem) {
        const session = JSON.parse(sessionItem.value)
        const expiresAt = session.expires_at * 1000 // 转为毫秒
        const now = Date.now()

        // 如果 session 未过期（留 5 分钟余量），直接使用
        if (expiresAt - now > 5 * 60 * 1000) {
          console.log(`✅ Using existing auth state for ${account.name}`)
          return
        }
      }
    } catch (error) {
      console.log(`⚠️ Failed to parse existing auth state: ${error}`)
    }
  }

  console.log(`🔐 Creating fresh auth state for ${account.name}...`)

  const browser = await chromium.launch()
  const page = await browser.newPage()

  try {
    // 访问登录页面
    await page.goto(`${baseURL}/login`, { waitUntil: 'networkidle' })

    // 填写登录表单
    await page.fill('#email', account.email)
    await page.fill('#password', account.password)

    // 点击登录按钮
    await page.getByRole('button', { name: /登录/ }).click()

    // 等待登录完成（检查 URL 不再是 /login）
    await page.waitForURL(url => !url.pathname.includes('/login'), {
      waitUntil: 'networkidle',
      timeout: 30000
    })

    // 等待 localStorage 写入
    await page.waitForTimeout(500)

    // 验证登录成功
    const currentURL = page.url()
    if (currentURL.includes('/login')) {
      throw new Error('登录后仍停留在登录页面，可能登录失败')
    }

    console.log(`✅ Login successful, current URL: ${currentURL}`)

    // 保存 auth state
    await fs.promises.mkdir(path.dirname(account.statePath), { recursive: true })
    await page.context().storageState({ path: account.statePath })

    console.log(`✅ Auth state saved to ${account.statePath}`)
  } catch (error) {
    console.error(`❌ Failed to create auth state for ${account.name}:`, error)
    throw error
  } finally {
    await browser.close()
  }
}

const globalSetup = async (config: FullConfig) => {
  const baseURL = config.projects[0]?.use?.baseURL as string | undefined

  if (!baseURL) {
    throw new Error('Playwright baseURL 未配置，无法执行登录步骤')
  }

  // 等待 dev 服务器就绪
  await waitForDevServer(baseURL)

  const accounts: Account[] = [
    {
      name: 'teacher',
      email: process.env.PLAYWRIGHT_TEACHER_EMAIL || 'playwright-teacher@test.com',
      password: process.env.PLAYWRIGHT_TEACHER_PASSWORD || 'Playwright123!',
      statePath: path.join(AUTH_DIR, 'teacher.json'),
    },
    {
      name: 'student',
      email: process.env.PLAYWRIGHT_STUDENT_EMAIL || 'playwright-student@test.com',
      password: process.env.PLAYWRIGHT_STUDENT_PASSWORD || 'Playwright123!',
      statePath: path.join(AUTH_DIR, 'student.json'),
    },
  ]

  for (const account of accounts) {
    await ensureAuthState(baseURL, account)
  }
}

export default globalSetup
```

1. ✅ 添加 dev 服务器就绪检测
2. ✅ 检查 auth state 有效期，避免重复登录
3. ✅ 修正登录后的 URL 验证逻辑
4. ✅ 添加详细的日志输出
5. ✅ 更好的错误处理

## 🔍 问题 3：教师端作业管理偶发报错

### 问题现象
```
- 教师点击"作业管理"或"布置作业"时，先出现两次错误提示
- 随后页面可加载
- 返回其他页面后出现"一直加载中"卡死
- 终端无异常日志
- 浏览器 console 主要输出 Fast Refresh
```

### 根本原因分析（推测）

#### 3.1 RLS 权限问题
```
可能原因：
- 前端 Supabase client 只有 localStorage session
- 无服务器可读 cookie
- RLS 查询被拒绝
- loadAssignments 抛错并 alert
```

#### 3.2 useEffect 重复执行
```javascript
useEffect(() => {
  loadAssignments() // 每次渲染都执行
}, []) // 依赖项可能不完整

useEffect(() => {
  loadAssignments()
}, [filters]) // 筛选器变化时执行

// 可能导致：
// - 初次加载时 loadAssignments 被调用 2 次
// - 每次都 alert 错误 → 双重弹窗
```

#### 3.3 路由状态未恢复
```
可能原因：
- RSC 请求失败
- router.back() 后 state 未恢复
- 组件卡在 loading=true
```

## ✅ 问题 3 解决方案

### 方案 A：修复 useEffect 重复调用

**需要先定位作业管理页面文件（当前不存在）：**

假设文件为 `src/app/teacher/assignments/page.tsx`，应该这样修复：

```typescript
// src/app/teacher/assignments/page.tsx (示例)
'use client'

import { useEffect, useState, useCallback } from 'react'
import { supabase } from '@/lib/supabase'

export default function TeacherAssignmentsPage() {
  const [assignments, setAssignments] = useState([])
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState<string | null>(null)
  const [filters, setFilters] = useState({ status: 'all' })

  // 使用 useCallback 避免重复创建函数
  const loadAssignments = useCallback(async () => {
    try {
      setLoading(true)
      setError(null) // 清除旧错误

      const { data, error: fetchError } = await supabase
        .from('assignments')
        .select('*')
        .order('created_at', { ascending: false })

      if (fetchError) {
        // 详细的错误日志
        console.error('[loadAssignments] Supabase error:', {
          code: fetchError.code,
          message: fetchError.message,
          details: fetchError.details,
          hint: fetchError.hint,
        })

        // 不要立即 alert，改为设置状态
        setError(`加载失败：${fetchError.message}`)
        return
      }

      setAssignments(data || [])
    } catch (err: any) {
      console.error('[loadAssignments] Unexpected error:', err)
      setError('加载作业列表时发生未知错误')
    } finally {
      setLoading(false)
    }
  }, []) // 无依赖，只创建一次

  // 初次加载
  useEffect(() => {
    loadAssignments()
  }, [loadAssignments]) // 依赖 loadAssignments（稳定的）

  // 筛选器变化时重新加载
  useEffect(() => {
    if (!loading) { // 避免初次加载时重复
      loadAssignments()
    }
  }, [filters, loadAssignments])

  // 错误提示改为 UI 显示，不用 alert
  if (error) {
    return (
      <div className="p-8">
        <div className="rx-card bg-red-500/10 border-red-500/50 p-6">
          <h3 className="text-lg font-semibold text-red-400 mb-2">加载失败</h3>
          <p className="text-red-300 mb-4">{error}</p>
          <button
            onClick={loadAssignments}
            className="rx-btn rx-btn-primary"
          >
            重试
          </button>
        </div>
      </div>
    )
  }

  if (loading) {
    return (
      <div className="flex items-center justify-center min-h-[60vh]">
        <div className="text-muted">加载中...</div>
      </div>
    )
  }

  return (
    <div className="p-8">
      <h1 className="text-3xl font-bold mb-6">作业管理</h1>
      {/* ... 作业列表 UI ... */}
    </div>
  )
}
```

**改进点：**
1. ✅ 使用 `useCallback` 避免重复创建函数
2. ✅ 改 `alert` 为 UI 错误提示
3. ✅ 详细的错误日志（包含 code、details、hint）
4. ✅ 避免 useEffect 重复调用
5. ✅ 添加重试按钮

### 方案 B：添加全局错误处理

```typescript
// src/components/ErrorBoundary.tsx
'use client'

import React from 'react'

interface Props {
  children: React.ReactNode
}

interface State {
  hasError: boolean
  error?: Error
}

export class ErrorBoundary extends React.Component<Props, State> {
  constructor(props: Props) {
    super(props)
    this.state = { hasError: false }
  }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error('[ErrorBoundary] Caught error:', error, errorInfo)
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="min-h-screen flex items-center justify-center p-8">
          <div className="rx-card max-w-md w-full bg-red-500/10 border-red-500/50 p-6">
            <h2 className="text-2xl font-bold text-red-400 mb-4">出错了</h2>
            <p className="text-red-300 mb-4">
              {this.state.error?.message || '页面加载时发生错误'}
            </p>
            <button
              onClick={() => window.location.reload()}
              className="rx-btn rx-btn-primary w-full"
            >
              刷新页面
            </button>
          </div>
        </div>
      )
    }

    return this.props.children
  }
}
```

```sql
-- 检查 assignments 表的 RLS 策略
SELECT
  schemaname,
  tablename,
  policyname,
  permissive,
  roles,
  cmd,
  qual,
  with_check
FROM pg_policies
WHERE tablename = 'assignments';

-- 确保教师可以查看自己创建的作业
CREATE POLICY "教师可以查看自己的作业"
  ON assignments
  FOR SELECT
  USING (auth.uid() = created_by);

-- 确保教师可以创建作业
CREATE POLICY "教师可以创建作业"
  ON assignments
  FOR INSERT
  WITH CHECK (
    auth.uid() IN (
      SELECT id FROM profiles WHERE role = 'teacher'
    )
  );
```
